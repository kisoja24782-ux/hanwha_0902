## 2. 출력 파서 공통 원리

```
prompt(+ 형식 지시문) ──▶ LLM ──▶ 텍스트 ──▶ parser.parse() ──▶ 구조화된 값
```

모든 파서가 **두 가지 일**을 한다.

1. `get_format_instructions()` — 모델에게 "이런 형식으로 답하라"고 알려 줄 **지시문 문자열**을 만든다. → 프롬프트에 끼워 넣는다.
2. `parse(text)` — 모델이 준 텍스트를 실제 타입으로 **변환**한다. → 체인 끝에 `| parser`로 붙이면 자동 호출.

프롬프트에 지시문을 넣는 방식은 노트북마다 같다.

```python
prompt = PromptTemplate(
    template="...{format_instructions}\n{question}",
    input_variables=["question"],
    partial_variables={"format_instructions": parser.get_format_instructions()},  # partial로 고정
)
chain = prompt | llm | parser
```

## 3. ch06_01~02 — `PydanticOutputParser`, `with_structured_output`

### 3.1 파서를 쓰지 않을 때

이메일 본문(김철수 상무 → 이은채 대리, ZENESIS 자전거 유통 협력 및 1월 15일 미팅 제안)을 주고 "중요한 내용을 추출해 달라"고 했더니, 글머리 기호 요약 **문자열**이 나왔다.

- 사람이 읽기엔 좋지만 발신자, 날짜 같은 **특정 항목만 꺼내려면 문자열을 다시 해석**해야 한다 → 자동화가 어렵다.
- `stream_response(answer, return_output=True)`: 스트리밍 출력을 화면에 보여 주면서 **전체 텍스트를 변수로도 돌려받는** 옵션.

### 3.2 Pydantic 모델로 원하는 구조 정의

```python
class EmailSummary(BaseModel):
    person:  str = Field(description="메일을 보낸 사람")
    email:   str = Field(description="메일을 보낸 사람의 이메일 주소")
    subject: str = Field(description="메일 제목")
    summary: str = Field(description="메일 본문을 요약한 테스트")     # '텍스트'의 오타
    date:    str = Field(description="메일 본문에 언급된 미팅 날짜와 시간")

parser = PydanticOutputParser(pydantic_object=EmailSummary)
print(parser.get_format_instructions())
```

- `Field(description=...)`의 설명이 **그대로 모델에게 전달되는 지시**가 된다. 설명이 곧 프롬프트이므로 명확하게 써야 한다.
- `get_format_instructions()`는 "이 JSON 스키마에 맞게 출력하라"는 영어 안내문 + `EmailSummary`의 JSON 스키마(`properties`, `required`)를 만들어 준다.

### 3.3 프롬프트 → 모델 → 파서

```python
prompt = PromptTemplate.from_template("""
You are a helpful assistant. Please answer the following question in KOREAN.

QUESTION:{question}

EMAIL CONVERSATION: {email_conversation}

FORMAT: {format}
""")
prompt = prompt.partial(format=parser.get_format_instructions())
```

두 가지 사용 방식

```python
# (a) 단계별: 모델 출력(텍스트) → parser.parse()
output = stream_response(chain.stream({...}), return_output=True)   # ```json ... ``` 블록 문자열
structured_output = parser.parse(output)      # EmailSummary(person='김철수', ...)
structured_output.person                       # '김철수'

# (b) 체인에 파서 연결: 한 번에 객체 반환
chain = prompt | llm | parser
chain.invoke({...})   # EmailSummary(...)
```

- 모델이 `` ```json ... ``` `` 코드블록으로 감싸서 답해도 파서가 알아서 벗겨 내고 파싱한다.
- 결과는 `dict`가 아닌 **Pydantic 객체**여서 `structured_output.person`처럼 속성으로 접근하고, 필드 타입/필수 여부를 검증받는다.
- ⚠️ 같은 프롬프트인데 `date` 값이 실행마다 다르다: (a)는 `'2024-01-15T10:00:00'`(모델이 연도를 지어냄), (b)는 `'1월 15일 오전 10시'`(본문 그대로). `date`를 `str`로 두고 형식을 지정하지 않았기 때문. → 형식이 중요하면 설명에 형식을 명시하거나 `datetime` 타입/ `DatetimeOutputParser`(ch06_08)를 쓴다.

### 3.4 `with_structured_output()` — 모델에 스키마를 직접 바인딩

```python
llm.invoke("대한민국의 수도는 뭐야 ?")     # 일반 호출 → AIMessage (구조화 X)

llm_with_structured = ChatOpenAI(model="gpt-4o-mini", temperature=0).with_structured_output(EmailSummary)
answer = llm_with_structured.invoke(email_conversation)     # EmailSummary 객체가 바로 반환
answer.person
```

- 프롬프트에 형식 지시문을 넣고 파서를 붙이는 과정을 **모델 쪽에 위임**한다 (내부적으로 모델의 도구 호출/구조화 출력 기능 사용). 코드가 훨씬 짧다.
- 프롬프트 없이 이메일 본문만 넘겼다.
- ⚠️ 결과 `answer.person`이 `'이은채'`로 나왔다. 이메일의 **보낸 사람은 김철수**, 이은채는 받는 사람이다. `"메일을 보낸 사람"`이라는 설명만으로는 모호했던 것 → **지시 없이 스키마 설명만 주면 엉뚱한 값을 채울 수 있으니 결과 검증이 필요**하다.
- 정리: 파서 방식은 **프롬프트에 지시문을 넣고 텍스트를 사후 파싱**, `with_structured_output`은 **모델이 애초에 구조화된 결과를 반환**하게 한다.

## 4. ch06_04 — `CommaSeparatedListOutputParser`

쉼표로 구분된 답을 **파이썬 리스트**로 바꾼다.

```python
output_parser = CommaSeparatedListOutputParser()
format_instructions = output_parser.get_format_instructions()
# 'Your response should be a list of comma separated values, eg: `foo, bar, baz` or `foo,bar,baz`'

prompt = PromptTemplate(
    template="List five {subject}.\n{format_instructions}",
    input_variables=["subject"],
    partial_variables={"format_instructions": format_instructions},
)
chain = prompt | ChatOpenAI(temperature=0) | output_parser

chain.invoke({"subject": "대한민국 관광명소"})
# ['경복궁', '남산타워', '부산 해운대해수욕장', '제주도 성산일출봉', '경주 불국사temples']
```

- 지시문이 매우 단순하다. 별도 스키마 없이 "쉼표로 구분해서 5개"만 요구한다.
- 결과 마지막 항목이 `'경주 불국사temples'`로 깨져 있다 → 모델 출력 품질 문제(파서는 쉼표로 자르기만 함). 기본 모델(`ChatOpenAI()`)이라 일어난 현상으로 보인다. 이 셀은 `gpt-4o-mini`로 만든 `llm`이 아닌 새로 만든 `model = ChatOpenAI(temperature=0)`를 썼다.
- **스트리밍 특성**: `chain.stream()`을 돌리면 항목이 완성될 때마다 **각각 별개의 리스트**(`['경복궁']`, `['남산타워']`, …)로 나온다. 노트북 주석대로 "토큰 단위로 별개 리스트가 되어 활용성이 떨어진다". 리스트 전체가 필요하면 `invoke`를 쓴다.

## 5. ch06_05 — `StructuredOutputParser` (구조화된 출력 파서)

**키-값 쌍을 가진 딕셔너리**로 받고 싶을 때 쓴다. Pydantic 클래스 없이 `ResponseSchema` 목록으로 필드를 정의한다.

```python
from langchain_classic.output_parsers import ResponseSchema, StructuredOutputParser

response_schemas = [
    ResponseSchema(name="answer", description="사용자의 질문에 대한 답변"),
    ResponseSchema(name="source", description="사용자의 질문에 답하기 위해 사용된 '출처', '웹사이트 주소' 이어야 합니다."),
]
output_parser = StructuredOutputParser.from_response_schemas(response_schemas)
print(output_parser.get_format_instructions())
```

지시문 출력: `` ```json { "answer": string // ..., "source": string // ... } ``` ``` 형식으로 답하라는 안내 (필드별 주석으로 description 포함).

```python
prompt = PromptTemplate(
    template="answer the users question as best as possible.\n{format_instructions}\n{question}",
    input_variables=["question"],
    partial_variables={"format_instructions": format_instructions},
)
chain = prompt | ChatOpenAI(temperature=0) | output_parser
chain.invoke({"question": "나이지리아의 수도는 어디인가요 ?"})
# {'answer': '나이지리아의 수도는 아부자입니다.', 'source': 'https://ko.wikipedia.org/wiki/...'}
```

- 결과는 **`dict`** (`result["answer"]`).
- 노트북 주석: 로컬(소형) 모델은 이해력이 부족할 수 있으므로 **`description`을 영어로 쓰는 편이 안정적**이다. 이 파서는 그런 모델에서도 형식을 비교적 잘 맞추게 도와준다.
- `source`(출처 URL)는 모델이 만들어 낸 값이라 **실제로 존재하는 주소인지 별도 확인**이 필요하다 (환각 가능).
- Pydantic 방식(3장)과 비교: 타입 검증이 없고 모든 값이 문자열이라 **가볍고 간단**하다.

## 6. ch06_06 — `JsonOutputParser`

지정한 스키마에 맞는 **JSON을 파싱해 `dict`로** 돌려준다.

```python
class Topic(BaseModel):
    description: str = Field(description="주제에 대한 간결한 설명")
    hashtag:     str = Field(description="해시태그 형식의 키워드(2개 이상)")

parser = JsonOutputParser(pydantic_object=Topic)     # 스키마 정의는 Pydantic으로
print(parser.get_format_instructions())
```

- 지시문 맨 앞에 `STRICT OUTPUT FORMAT:` 규칙이 붙는다: **JSON 값만 반환, 마크다운 코드펜스(```) 금지, 앞뒤 설명문 금지, 후행 쉼표/주석 금지.**
- 이어서 JSON 스키마가 나온다. (노트북에 찍힌 지시문은 앞의 Pydantic 파서보다 엄격한 문구다.)

```python
prompt = ChatPromptTemplate.from_messages([
    ("system", "당신은 친절한 AI 어시스턴트 입니다. 질문에 간결하게 답변하세요"),
    ("user", "#Format: {format_instructions}\n\n#Question: {question}"),   # "user"는 "human"과 같은 역할
])
prompt = prompt.partial(format_instructions=parser.get_format_instructions())

chain = prompt | llm | parser
answer = chain.invoke({"question": "지구 온난화의 심각성에 대해 알려주세요."})
answer["description"]     # dict 접근
```

- `JsonOutputParser`는 스키마를 **지시문 생성용**으로만 쓰고, 결과는 검증된 객체가 아니라 **그냥 `dict`**다. (`PydanticOutputParser`는 결과가 검증된 객체.)
- 노트북 설명: **원하는 JSON을 안정적으로 만들려면 모델 용량이 충분히 커야** 하고, 작은 모델은 오류가 잘 난다.
- `ChatPromptTemplate`에 `.partial()`도 사용 가능 (ex_0915에서 `PromptTemplate`로 배운 내용과 동일).

## 7. ch06_07 — `PandasDataFrameOutputParser`

LLM이 **자연어 질문을 pandas 연산 명령 문자열로 번역**하고, 파서가 그 명령을 **실제 DataFrame에 실행**해 결과를 준다.

### 7.1 데이터와 파서

```python
df = pd.read_csv("./titanic.csv")          # 승객 20행: PassengerId, Survived, Pclass, Name, Sex, Age, SibSp, Parch, Ticket, Fare, Cabin, Embarked
parser = PandasDataFrameOutputParser(dataframe=df)
print(parser.get_format_instructions())
```

지시문이 요구하는 명령 형식: **`연산:대상[범위]`**

| 예 | 의미 |
|---|---|
| `column:Age` | Age 열 전체 |
| `row:1` | 1번 행 |
| `column:Age[1,2]` | Age 열의 1, 2번 행 |
| `row:1[Age]` | 1번 행의 Age 값만 |
| `mean:Age[1..3]` | 1~3번 행 Age의 평균 (`[0..4]`처럼 범위 표기) |

- 지시문에 **사용 가능한 컬럼 목록**이 자동으로 들어간다. 없는 컬럼/잘못된 연산이면 `"Invalid column"`, `"Invalid operation"`으로 시작하는 문장으로 답하도록 안내한다.

### 7.2 따옴표 문제와 해결 (`strip_quotes`)

```python
def strip_quotes(text):
    """LLM이 씌운 따옴표를 제거한다. ..."""
    return text.strip().strip('"').strip("'").strip()

chain = prompt | llm | StrOutputParser() | RunnableLambda(strip_quotes) | parser
```

- 문제: 모델이 `"column:Age"`처럼 **따옴표까지 붙여** 답하면 파서가 `:`로 자를 때 요청 타입이 `column`이 아니라 `"column`이 되어 `OutputParserException`이 난다. (첫 셀의 주석 `# "Age" 컬럼 오류 떄문에`가 이 오류 때문에 `StrOutputParser`, `RunnableLambda`를 import했다는 뜻.)
- 해결: `모델 → StrOutputParser(문자열 추출) → RunnableLambda(strip_quotes)(따옴표 제거) → 파서`. **파서 앞에 전처리 단계를 끼워 넣는** 좋은 사례다.
- 결과 Series를 보기 좋게 출력하려고 `format_parser_output()`을 정의: 값들을 `.to_dict()`로 바꾸고 `pprint`로 출력.

### 7.3 질의 결과

| 질문(영어) | 반환 | 설명 |
|---|---|---|
| `Retrieve the Age column` | `{'Age': {0: 22.0, 1: 38.0, ..., 5: nan, ...}}` | 열 조회. 결측치는 `nan` |
| `Retrieve the first row` | `{'0': {'Age': 22.0, 'Cabin': nan, 'Embarked': 'S', ...}}` | 행 조회 |
| `Retrieve the average of the Ages from row 0 to 4.` | `{'mean': np.float64(31.2)}` | 평균. `df["Age"].head().mean()` = 31.2로 검증 |
| `Calculate average 'Fare' rate.` | `{'mean': np.float64(22.19937)}` | 평균. `df["Fare"].mean()`과 일치 |

- 열/행 조회는 결과가 Series라 `format_parser_output`으로 dict 변환이 필요하지만, `mean` 같은 연산 결과는 단일 값이라 그대로 `print`했다.
- 파서 결과를 **직접 pandas 코드로 확인**(`df["Fare"].mean()`)해 일치하는지 검증하는 흐름이 좋다.
- 참고: `titanic.csv`는 **20행짜리 샘플**이라 Fare 평균 22.2는 전체 타이타닉 데이터의 평균과 다르다.
- 질문을 **영어**로 쓴 점에 주목: 지시문이 영어이고 연산명(`mean` 등)을 정확히 맞춰야 하기 때문.

## 8. ch06_08 — `DatetimeOutputParser`

LLM 답을 **`datetime` 객체**로 바꾼다.

```python
output_parser = DatetimeOutputParser()
output_parser.format = "%Y-%m-%d"                 # 날짜 형식 지정 (기본은 ISO 형태에 시각·밀리초 포함)
print(output_parser.get_format_instructions())
# Write a datetime string that matches the following pattern: '%Y-%m-%d'.
# Examples: 2026-09-16, 2025-09-16, 2026-09-15
# Return ONLY this string, no other words!
```

```python
prompt = PromptTemplate.from_template(template, partial_variables={"format_instructions": output_parser.get_format_instructions()})
chain = prompt | ChatOpenAI() | output_parser
output = chain.invoke({"question": "Google이 창업한 연도"})
output.strftime("%Y-%m-%d")      # '1998-09-04'
```

- `format`에는 `strftime` 형식 코드(`%Y-%m-%d`)를 쓰고, 지시문의 **예시 날짜는 파서가 자동 생성**한다 (실행 시점 기준 날짜가 반영됨).
- 결과는 문자열이 아닌 **`datetime` 객체**라서 날짜 계산/포맷 변경이 바로 가능하다 (`strftime`으로 다시 문자열화).
- 프롬프트 양식은 `#Format Instructions / #Question / #Answer:` 구조. `PromptTemplate.from_template(..., partial_variables=...)`로 바로 partial을 넣은 방식도 확인.
- ch06_01~02에서 `date`를 `str`로 받았을 때 형식이 흔들렸던 문제에 대한 대안이 이 파서다.

## 9. ch06_09 — `EnumOutputParser`

답을 **미리 정한 후보 중 하나(`Enum` 멤버)**로만 받고 싶을 때 쓴다. 분류 작업에 적합하다.

```python
class Colors(Enum):
    RED   = "빨간색"
    GREEN = "초록색"
    BLUE  = "파란색"

parser = EnumOutputParser(enum=Colors)
parser.get_format_instructions()
# 'Select one of the following options: 빨간색, 초록색, 파란색'
```

```python
prompt = PromptTemplate.from_template("""What color is the following object ?

Object : {object}

Instructions: {instructions}""").partial(instructions=parser.get_format_instructions())

chain = prompt | ChatOpenAI() | parser
response = chain.invoke({"object": "사과"})
response            # Colors.RED
type(response)      # <enum 'Colors'>
response.value      # '빨간색'
```

- 파서는 모델의 답을 **Enum의 "값"(여기선 '빨간색')과 매칭**해 해당 멤버(`Colors.RED`)를 돌려준다. 이름(`RED`)이 아니라 **값**에 맞춰 지시문이 만들어진다.
- 후보 밖의 답이 나오면 파싱 오류가 나므로, 결과 범위가 보장된다 → 이후 코드에서 `if response == Colors.RED:`처럼 안전하게 분기 가능.
- `.partial(...)`을 `from_template()` 뒤에 바로 이어 붙이는 체이닝 문법도 볼 수 있다.

## 10. 파서 선택 가이드 (한 장 요약)

| 파서 | 결과 | 검증 | 언제 쓰나 |
|---|---|---|---|
| `StrOutputParser` | `str` | - | 텍스트만 필요 (ex_0914에서 사용) |
| `CommaSeparatedListOutputParser` | `list[str]` | - | 간단한 항목 나열. 스트리밍 시 조각남 |
| `StructuredOutputParser` | `dict` | 약함 (문자열) | 가볍게 키-값 몇 개 받기 |
| `JsonOutputParser` | `dict` | 약함 | JSON 구조가 필요하지만 객체까지는 불필요 |
| `PydanticOutputParser` | Pydantic 객체 | **강함** (타입·필수) | 스키마가 명확하고 검증이 필요 |
| `.with_structured_output(Schema)` | Pydantic 객체 | 강함 | 최신 방식, 코드가 가장 짧음 (모델 기능 사용) |
| `PandasDataFrameOutputParser` | `dict` (Series/값) | 컬럼/연산 검증 | 자연어로 DataFrame 조회·집계 |
| `DatetimeOutputParser` | `datetime` | 형식 검증 | 날짜/시간 추출 |
| `EnumOutputParser` | `Enum` | 후보 밖이면 오류 | 정해진 범주로 분류 |


## 11. 공부하며 기억할 함정

1. **`get_format_instructions()`를 프롬프트에 꼭 넣어야** 한다. 파서만 붙이고 지시문이 없으면 모델이 자유 형식으로 답해 파싱이 실패한다.
2. `Field(description=)`, `ResponseSchema(description=)` 같은 **설명이 곧 프롬프트**다. 모호하면 값이 뒤바뀐다 (`with_structured_output`이 보낸 사람을 이은채로 채운 사례).
3. 필드를 `str`로만 두면 **형식이 실행마다 달라질 수** 있다 (`date`가 ISO 문자열 vs '1월 15일 오전 10시'). 형식이 중요하면 전용 파서나 설명에 형식을 명시한다.
4. `PandasDataFrameOutputParser`는 모델이 **따옴표를 붙이면 실패**한다 → `RunnableLambda`로 전처리 단계를 끼워 넣는다.
5. 파서 뒤에 오는 결과 타입이 파서마다 다르다: 객체(`.person`) / dict(`["answer"]`) / list / datetime / Enum(`.value`).
6. 리스트 파서를 `stream()`하면 조각난 리스트가 나온다. 전체가 필요하면 `invoke()`.
7. 기본 `ChatOpenAI()`(구형 모델)는 형식 준수가 불안정하다 (`'경주 불국사temples'` 같은 깨짐). `model="gpt-4o-mini"`, `temperature=0`을 명시하자.
8. **LLM이 만든 값은 검증 대상**이다: `source` URL, `date`의 연도, 평균값 등은 원본·직접 계산과 대조한다.
9. `langchain_classic`에서 import 해야 하는 파서가 있다 (`ResponseSchema`, `StructuredOutputParser`, `PandasDataFrameOutputParser`, `DatetimeOutputParser`, `EnumOutputParser`). `ImportError`가 나면 import 경로를 확인한다.
10. 몇몇 노트북에 **선언만 하고 쓰지 않는 코드**가 있다 (`llm`을 만들고 `ChatOpenAI()`를 새로 생성해 사용, `from itertools import chain`이 이후 `chain = ...`에 덮어쓰임, 안 쓰는 import 다수). 공부할 때는 실제로 실행에 쓰인 객체가 무엇인지 확인하며 읽자.
