## 3. ch04 — `ChatOpenAI` 기본 사용

### 3.1 모델 생성과 호출

```python
from langchain_openai import ChatOpenAI

llm = ChatOpenAI(temperature=0.1, model="gpt-4o-mini")
response = llm.invoke("호주의 수도는 어디인가요 ?")
```

- `temperature`: 낮을수록 일관되고 보수적인 답, 높을수록 다양한 답.
- `invoke(문자열)`: 응답이 **완전히 끝난 뒤** `AIMessage` 객체 하나를 돌려준다.

### 3.2 응답(`AIMessage`) 구조

| 접근 | 내용 |
|---|---|
| `response.content` | 답변 텍스트 |
| `response.response_metadata` | 토큰 사용량, 모델명, `finish_reason` 등 메타데이터 |
| `response.response_metadata["token_usage"]["total_tokens"]` | 총 토큰 수 (예: 54 = 프롬프트 15 + 답변 39) |
| `response.usage_metadata` | 입력/출력/총 토큰을 표준화한 형태 |

### 3.3 logprobs (로그 확률)

```python
llm_with_logprob = ChatOpenAI(
    temperature=0.1, max_completion_tokens=2048, model="gpt-4o-mini"
).bind(logprobs=True)
```

- `.bind(...)`: 모델 호출 시 항상 붙일 파라미터를 미리 고정한 새 Runnable을 만든다.
- `response.response_metadata["logprobs"]["content"]`에 **토큰마다** `token`, `bytes`, `logprob`이 들어 있다.
- `logprob`이 **0에 가까울수록 확신이 높다** (0 → 확률 100%, -1.16 → 약 31%). 예: `'.'`은 0.0, `' 연'`은 -1.16으로 상대적으로 덜 확신.
- 한글이 `' \xec\xba'`처럼 깨져 보이는 토큰은 글자 하나가 여러 바이트 토큰으로 쪼개진 것이다.
- `top_logprobs`가 비어 있는 이유: 후보 토큰 수(`top_logprobs=N`)를 따로 지정하지 않았기 때문.

### 3.4 스트리밍

```python
answer = llm.stream("호주의 아름다운 관광지 10곳과 주소를 알려주세요")
for token in answer:
    print(token.content, end="", flush=True)
```

- `stream()`은 토큰 조각(chunk)을 생성되는 대로 내보내는 제너레이터.
- `end=""`(줄바꿈 방지) + `flush=True`(즉시 출력)로 타자 치듯 출력한다.

## 4. ch04_2 — 멀티모달 (이미지 입력)

### 4.1 `langchain_teddynote`의 `MultiModal`

```python
from langchain_teddynote.models import MultiModal
from langchain_teddynote.messages import stream_response

multimodal_llm = MultiModal(llm)
answer = multimodal_llm.stream(IMAGE_URL)   # URL 또는 로컬 경로 모두 가능
stream_response(answer)                     # 스트림을 받아 화면에 출력
```

- 웹 이미지 URL(표 이미지)과 로컬 파일 `./sample-image.png`(OpenAI DevDay 요약 이미지) 모두 같은 방식으로 호출한다.
- 프롬프트를 주지 않으면 라이브러리 기본 프롬프트로 이미지를 설명한다.

### 4.2 직접 만든 `image_url()` — 이미지 → 전송 가능한 문자열

```python
def image_url(image_source):
    if str(image_source).startswith(("http://", "https://")):
        return str(image_source)          # 웹 URL은 그대로 (OpenAI 서버가 직접 다운로드)
    image_path = Path(image_source)
    mime_type = "image/png" if image_path.suffix.lower() == ".png" else "image/jpeg"
    encoded = base64.b64encode(image_path.read_bytes()).decode("utf-8")
    return f"data:{mime_type};base64,{encoded}"     # data URL 규격
```

- 로컬 파일은 API 서버가 접근할 수 없으므로 **바이트 → base64 → 문자열**로 바꿔 요청에 실어 보낸다.
- `b64encode`는 `bytes`를 반환하므로 `.decode("utf-8")`가 필요.
- MIME 타입은 확장자로만 판단하는 단순 방식 (png 외에는 전부 jpeg 취급). webp/gif는 별도 처리가 필요.

### 4.3 `stream_image_response()` — 메시지 직접 조립

```python
content = [
    {"type": "text", "text": user_prompt},
    {"type": "image_url", "image_url": {"url": image_url(image_source)}},
]
messages = [HumanMessage(content=content)]
if system_prompt:
    messages.insert(0, SystemMessage(content=system_prompt))   # 시스템 메시지는 맨 앞
for token in llm.stream(messages):
    print(token.content, end="", flush=True)
```

- **멀티모달 메시지의 `content`는 문자열이 아니라 "블록 리스트"** (텍스트 블록 + 이미지 블록).
- 시스템 메시지는 대화의 첫 번째여야 하므로 `append`가 아니라 `insert(0, ...)`.
- `MultiModal` 라이브러리가 내부에서 해주는 일을 직접 풀어 쓴 코드라고 보면 된다.

### 4.4 시스템/사용자 프롬프트 지정

```python
multimodal_llm_with_prompt = MultiModal(llm, system_prompt=system_prompt, user_prompt=user_prompt)
```

- system: "재무제표를 해석하는 금융 AI 어시스턴트" (역할 부여)
- user: "표는 회사 재무제표다. 흥미로운 사실을 정리하라" (구체적 요청)
- 재무제표 이미지를 넣어 요약을 받는다.
- ⚠️ 출력 결과 1번 항목이 제목은 "유동자산 **증가**"인데 내용은 감소(8,602,837 → 8,349,633)라고 설명한다. **LLM 이미지 해석은 제목/논리가 어긋날 수 있으니 검증이 필요**하다는 좋은 예시.

## 5. ch04_3 — 로깅과 함께 멀티모달 호출

> 파일 상단 마크다운 제목은 "프롬프트 템플릿"이지만 실제 내용은 **로깅 설정 + 멀티모달 호출**이다.

```python
logging.basicConfig(
    filename="app.log",          # 파일로만 기록 (콘솔에는 안 나옴), 기본 모드 'a'라 계속 누적
    level=logging.INFO,          # INFO 이상만 기록 (DEBUG 무시)
    format="%(asctime)s - %(levelname)s - %(message)s",
    encoding="utf-8",            # 윈도우에서 한글 깨짐 방지
)
logger = logging.getLogger("MyMultimodalApp")
```

핵심 포인트

- `basicConfig`는 **최초 1회만 적용**된다. 주피터에서 설정을 바꿔도 안 먹히면 커널을 재시작해야 한다.
- 로그 지점 배치: ① 시작 → ② **요청 직전(입력값 기록)** → ③ 스트리밍 시작 → ④ 처리 완료.
  어디까지 찍혔는지로 실패 지점을 좁힐 수 있다. (③까지 있고 ④가 없으면 스트리밍 중 실패)
- `except Exception as e: logger.error(..., exc_info=True)` → `exc_info=True`가 **전체 스택 트레이스**를 남긴다.
- `llm.stream()`은 제너레이터를 만들기만 하고, **실제 통신은 `stream_response()`가 소비하기 시작할 때** 일어난다. (지연 실행)
- 실행하면 `app.log` 파일이 생긴다.

## 6. ch04_4 — LCEL (LangChain Expression Language)

```python
prompt = PromptTemplate.from_template("{topic} 에 대해 쉽게 설명해주세요")
model  = ChatOpenAI(model="gpt-4o-mini", temperature=0.1)
chain  = prompt | model          # 파이프(|)로 연결

chain.invoke({"topic": "인공지능 모델의 학습 원리"}).content
chain.stream({"topic": "인공지능 모델의 학습 원리"})    # 스트리밍
```

- `chain = prompt | model | output_parser` 형태가 LCEL의 기본 문형. 왼쪽 출력이 오른쪽 입력이 된다.
- `PromptTemplate.from_template("...{변수}...")`: 문자열 속 `{변수}`를 나중에 딕셔너리로 채운다. **변수는 여러 개 가능**.
- 입력은 **딕셔너리**(`{"topic": ...}`). 키 이름이 템플릿 변수명과 같아야 한다.
- 체인은 `invoke` / `stream` / `batch` 등 모델과 같은 인터페이스를 그대로 가진다.

두 번째 예: 변수 2개

```python
prompt = PromptTemplate.from_template("{topic} 에 대해 쉽게 {how} 설명해주세요")
chain = prompt | ChatOpenAI()
chain.invoke({"topic": "인공지능 모델의 학습 원리", "how": "5살짜리도 이해하기 쉽게 설명해주세요"})
```

- `ChatOpenAI()`처럼 `model`을 생략하면 **기본값 `gpt-3.5-turbo`**가 쓰인다. 출력의 `profile`에 `GPT-3.5-turbo (deprecated)`로 찍혀 있다. 첫 예제만 `gpt-4o-mini`를 명시했다.

## 7. ch04_5 — 출력 파서 (`StrOutputParser`)

```python
from langchain_core.output_parsers import StrOutputParser

chain = prompt | model | StrOutputParser()
chain.invoke({"topic": "인공지능 모델의 학습원리"})   # AIMessage가 아니라 str 반환
```

- 파서가 없으면 결과가 `AIMessage` → `.content`로 꺼내야 한다. `StrOutputParser`를 붙이면 **바로 문자열**.
- 스트리밍 시에도 각 chunk가 문자열이 된다.

### 프롬프트 템플릿 활용 예: 영어 회화 선생님

```python
template = """
당신은 영어를 가르치는 10년차 영어 선생님입니다.
주어진 상황에 맞는 영어 회화를 작성해 주세요
양식은 [FORMAT]을 참고하여 작성해 주세요

#상황: {question}
# FORMAT :
- 영어 회화:
- 한글 해석:
"""
chain = PromptTemplate.from_template(template) | ChatOpenAI(model="gpt-4o-mini") | StrOutputParser()
chain.invoke({"question": "저는 식당에 가서 음식을 주문하고 싶어요"})
```

- 프롬프트 구성 요소: **역할 부여 → 지시 → 출력 양식(FORMAT) → 입력 변수**. 양식을 명시하면 답변 형태가 일정해진다.
- `chain.stream(...)` 결과를 `stream_response(answer)`로 출력. (`print(stream_response(...))`는 함수가 반환값이 없어 마지막에 `None`이 같이 찍힌다.)

## 8. ch04_6 — `batch`와 비동기 실행

### 8.1 실행 메서드 비교

| 메서드 | 방식 | 입력 → 출력 |
|---|---|---|
| `invoke` | 동기 | 단일 입력 → 단일 출력 |
| `stream` | 동기 | 단일 입력 → 데이터 스트림 |
| `batch` | 동기 | 입력 **리스트** → 출력 **리스트** |
| `ainvoke` | 비동기 | 단일 → 단일 |
| `astream` | 비동기 | 단일 → 스트림 |
| `abatch` | 비동기 | 리스트 → 리스트 |
| `astream_log` | 비동기 | 최종 응답뿐 아니라 **중간 단계 로그/상태**도 스트리밍 |

### 8.2 `batch`

```python
chain = PromptTemplate.from_template("{topic} 에 대하여 3문장으로 설명해줘") | ChatOpenAI() | StrOutputParser()

chain.batch([{"topic": "ChatGPT"}, {"topic": "Instagram"}])          # 2개를 한 번에 → 리스트 반환

chain.batch([...5개...], config={"max_concurrency": 3})              # 동시 실행 개수 제한
```

- 결과 리스트는 **입력 순서와 동일**하다.
- `max_concurrency`: 동시에 처리할 요청 수 제한 (5개 입력에 3 → 최대 3개씩 동시 처리). API rate limit 대응에 쓴다.

### 8.3 비동기

```python
async for token in chain.astream({"topic": "YouTube"}):
    print(token, end="", flush=True)

my_process = chain.ainvoke({"topic": "NVDA"})   # 코루틴만 만들어짐 (아직 실행 X)
print(await my_process)                         # await 해야 실제 실행
```

- 주피터에서는 셀 최상단에서 `async for` / `await`을 바로 쓸 수 있다. 일반 `.py`에서는 `asyncio.run(...)`이 필요.
- `ainvoke()`만 호출해서는 실행되지 않고 `await` 시점에 실행된다.
- 참고: 두 번째 마크다운 제목이 "batch() 함수로 일괄 처리하기"로 되어 있는데 실제 내용은 비동기 메서드 설명(제목 복붙 실수).

## 9. ch04_7 — Runnable 조합 (병렬 / 패스스루 / 람다)

### 9.1 `RunnableParallel` — 여러 체인을 동시에

```python
chain1 = PromptTemplate.from_template("{country} 의 수도는 어디야 ?") | model | StrOutputParser()
chain2 = PromptTemplate.from_template("{country} 의 면적은 얼마야 ?") | model | StrOutputParser()

combined = RunnableParallel(capital=chain1, area=chain2)
combined.invoke({"country": "대한민국"})
# {'capital': '대한민국의 수도는 서울이에요.', 'area': '대한민국의 면적은 약 100,363 km²이다.'}
```

- **같은 입력을 여러 체인에 동시에 넣고**, 키 이름(`capital`, `area`)별로 결과를 딕셔너리로 묶는다.
- `batch`도 동일하게 동작: 입력 2개 → 결과 딕셔너리 2개의 리스트.

### 9.2 `RunnablePassthrough` — 입력을 그대로 통과

```python
RunnablePassthrough().invoke({"num": 10})     # {'num': 10}  (입력 그대로)

prompt = PromptTemplate.from_template("{num} 의 10배는 ?")
chain = prompt | ChatOpenAI(temperature=0)
chain.invoke({"num": 5})     # 딕셔너리 입력
chain.invoke(5)              # 변수가 1개면 값만 넘겨도 동작

runnable_chain = {"num": RunnablePassthrough()} | prompt | ChatOpenAI()
runnable_chain.invoke(10)    # 10 → {"num": 10} 으로 감싸져 프롬프트에 들어감
```

- 체인 맨 앞에 `{"키": RunnablePassthrough()}`를 두면 **들어온 단일 값을 원하는 키에 매핑**해 준다.
- 딕셔너리 리터럴을 `|`로 연결하면 자동으로 `RunnableParallel`로 변환된다.

#### `RunnablePassthrough.assign` — 값을 추가하며 통과

```python
RunnablePassthrough.assign(new_num=lambda x: x["num"] * 3).invoke({"num": 1})
# {'num': 1, 'new_num': 3}    ← 기존 입력 유지 + 새 키 추가
```

#### 세 가지를 한 번에 조합

```python
runnable = RunnableParallel(
    passed   = RunnablePassthrough(),                                   # {'num': 1}
    extra    = RunnablePassthrough.assign(mult=lambda x: x["num"] * 3), # {'num': 1, 'mult': 3}
    modified = lambda x: x["num"] + 1,                                  # 2 (람다도 자동 변환)
)
runnable.invoke({"num": 1})
```

#### 단일 입력으로 병렬 체인

```python
chain1 = {"country": RunnablePassthrough()} | PromptTemplate.from_template("{country} 의 수도는 ?") | ChatOpenAI()
chain2 = {"country": RunnablePassthrough()} | PromptTemplate.from_template("{country} 의 면적은 ?") | ChatOpenAI()
RunnableParallel(capital=chain1, area=chain2).invoke("대한민국")   # 문자열만 넣어도 됨
```

- 여기서는 파서가 없어서 결과 값이 `AIMessage`다.

### 9.3 `RunnableLambda` — 파이썬 함수를 체인 단계로

```python
def get_today(a):
    return datetime.today().strftime("%b-%d")      # 'Sep-14'

prompt = PromptTemplate.from_template("{today} 가 생일인 유명인이나 가수 {n} 명을 나열하세요. 생년월일을 표기해 주세요.")
chain = (
    {"today": RunnableLambda(get_today), "n": RunnablePassthrough()}
    | prompt | llm | StrOutputParser()
)
chain.invoke(3)
```

- `today`는 함수 결과(오늘 날짜), `n`은 입력값(3)을 그대로 → 두 값이 프롬프트 변수로 합쳐진다.
- `get_today(a)`가 인자를 받는 이유: `RunnableLambda`에는 **입력이 항상 전달**되기 때문에 안 쓰더라도 매개변수 자리가 필요.

### 9.4 `itemgetter`로 딕셔너리에서 값 꺼내기

```python
from operator import itemgetter

chain = (
    {
        "a": itemgetter("word1") | RunnableLambda(length_function),           # len("hello") = 5
        "b": {"text1": itemgetter("word1"), "text2": itemgetter("word2")}
             | RunnableLambda(multiiple_length_function),                    # 5 * 5 = 25
    }
    | prompt | model
)
chain.invoke({"word1": "hello", "word2": "world"})   # "5 + 25 = 30"
```

- 입력 딕셔너리에서 **원하는 키만 뽑아** 다음 단계로 넘긴다.
- `RunnableLambda`가 받는 함수는 **인자 1개**여야 하므로, 여러 값을 쓰려면 딕셔너리로 묶어서 받는 래퍼(`multiiple_length_function`)를 만든다.
- 중첩 딕셔너리도 `RunnableParallel`로 변환된다.

### 10.2 도구(tool)를 가진 에이전트

```python
from langchain_core.tools import tool
from langchain.agents import create_agent

@tool
def get_weather(city: str) -> str:
    """Get weather for a given city"""          # docstring이 모델에게 주는 도구 설명
    return f"It's always sunny in {city} !"

agent = create_agent(model=ChatOpenAI(model="gpt-4o-mini", temperature=0), tools=[get_weather])
result = agent.invoke({"messages": [("user", "San Francisco 날씨 어때?")]})
print(result["messages"][-1].content)          # 마지막 메시지가 최종 답변
```

- `@tool`: 일반 함수를 LLM이 호출할 수 있는 도구로 만든다. **함수명·타입힌트·docstring**이 도구 스키마/설명이 된다.
- `create_agent`(langchain 1.x): 모델이 질문을 보고 **도구를 부를지 스스로 판단**하고, 도구 결과를 받아 최종 답을 만든다. (`langgraph` 기반)
- 입력/출력은 `{"messages": [...]}` 형태. 결과의 `messages`에는 사용자 질문 → 도구 호출 → 도구 결과 → 최종 답이 순서대로 쌓인다.

### 10.3 LangSmith 추적 켜고 끄기

```python
from langchain_teddynote import logging
```

- 별도의 코드 수정 없이 **환경변수 토글만으로** 동작한다.
- ch04_3의 `logging`(파이썬 표준 로깅, 로컬 파일)과 이름이 같아 헷갈리기 쉽지만 **다른 것**이다. 여기서는 `langchain_teddynote.logging`.

## 11. 개념 한 장 요약

```
문자열/딕셔너리 입력
   │
   ▼
PromptTemplate ──▶ ChatOpenAI ──▶ StrOutputParser ──▶ 결과(str)
 ({변수} 채우기)     (모델 호출)      (AIMessage → str)

      chain = prompt | model | parser        ← LCEL
```

| 실행 방식 | 언제 |
|---|---|
| `invoke` | 결과 하나가 필요할 때 |
| `stream` / `astream` | 답변을 실시간으로 보여줄 때 |
| `batch` (+`max_concurrency`) | 입력 여러 개를 한 번에 |
| `ainvoke` / `abatch` | 비동기 서버(FastAPI 등)에서 |

| Runnable 도구 | 한 줄 요약 |
|---|---|
| `RunnablePassthrough` | 입력 그대로 전달 (`assign`으로 키 추가) |
| `RunnableParallel` | 같은 입력을 여러 갈래로 동시에 실행, 딕셔너리로 묶기 |
| `RunnableLambda` | 파이썬 함수를 체인 단계로 사용 |
| `itemgetter` | 입력 딕셔너리에서 특정 키 추출 |
| `.bind()` | 모델 호출 옵션(예: `logprobs=True`)을 미리 고정 |

## 12. 공부하며 기억할 함정

1. `ChatOpenAI()`에 `model`을 생략하면 구형 `gpt-3.5-turbo`가 쓰인다 → 항상 `model=`을 명시.
2. 멀티모달 메시지의 `content`는 **블록 리스트**, 시스템 메시지는 **맨 앞**.
3. `stream()` / `ainvoke()`는 만들기만 해선 실행되지 않는다 (소비 / `await` 시점에 실행).
4. `logging.basicConfig`는 최초 1회만 적용 → 안 먹히면 커널 재시작.
5. 프롬프트 변수명과 입력 딕셔너리 키가 다르면 에러가 난다.
6. LLM의 이미지·표 해석 결과는 틀릴 수 있으니 원본과 대조한다 (ch04_2의 "증가/감소" 불일치 사례).
7. API 키는 `.env`로만 관리하고 출력할 때는 일부만 노출한다. 노트북 출력에 키가 남지 않게 주의.
