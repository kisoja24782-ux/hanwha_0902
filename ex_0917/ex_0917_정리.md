## 3. ch07_01 — OpenAI와 Anthropic

```python
gpt = ChatOpenAI(temperature=0, model="gpt-4o-mini")
stream_response(gpt.stream("사랑이 뭔가요?"))

from langchain_anthropic import ChatAnthropic
anthropic = ChatAnthropic(model="claude-sonnet-5")
stream_response(anthropic.stream("사랑이 뭔가요 ?"))
```

- 두 클래스 모두 `invoke` / `stream` / `batch` 인터페이스가 동일하다.
- Anthropic 셀 위 마크다운에 **"Claude 크레딧 충전해야함"**이라고 메모되어 있고, 이 셀은 출력이 저장돼 있지 않다 → **API 크레딧이 없어서 실행하지 못한 상태**로 보인다.
- 사용하려면 `.env`에 Anthropic API 키(`ANTHROPIC_API_KEY`)가 있어야 한다.
- `%pip install --upgrade pip`, `%pip install langchain-anthropic`처럼 셀 안에서 직접 패키지를 설치하는 흐름이 그대로 남아 있다.

## 4. ch07_03 — LLM 응답 캐싱

같은 질문을 또 보내면 **저장해 둔 답을 즉시 돌려줘서 시간과 API 비용을 아끼는** 기능.

```python
llm = ChatOpenAI(model="gpt-4o-mini")
prompt = PromptTemplate.from_template("{country}에 대해서 200자 내외로 요약해줘")
chain = prompt | llm
```

`%%time`(셀 실행 시간 측정 매직)으로 속도를 비교한다.

### 4.1 캐시 없음 (기준선)

- `chain.invoke({"country": "나이지리아"})` → **Wall time 2.22 s**

### 4.2 인메모리 캐시

```python
from langchain_classic.globals import set_llm_cache
from langchain_community.cache import InMemoryCache

set_llm_cache(InMemoryCache())      # 전역 설정 → 이후 모든 LLM 호출에 적용
chain.invoke(...)   # 1회차: 캐시에 없음 → 실제 호출 (답 저장)
chain.invoke(...)   # 2회차: 캐시 적중 → Wall time 7.91 ms (거의 즉시)
```

### 4.3 SQLite 캐시 (파일에 저장)

```python
from langchain_community.cache import SQLiteCache

if not os.path.exists("cache"):
    os.makedirs("cache")
set_llm_cache(SQLiteCache(database_path="cache/llm_cache.db"))
```

- 1회차 1.74 s → 2회차 **5.2 ms**.
- 같은 폴더에 `cache/llm_cache.db`가 실제로 생성되어 있다.

### 4.4 정리

| 항목 | 인메모리 | SQLite |
|---|---|---|
| 저장 위치 | 프로세스 메모리 | 디스크 파일 |
| 커널/프로그램 재시작 후 | 사라짐 | **유지됨** |
| 용도 | 실험, 짧은 세션 | 개발 중 반복 실행, 비용 절감 |

- `set_llm_cache()`는 **전역 설정**이다. 체인마다 지정하는 것이 아니라 한 번 지정하면 이후 모든 LLM 호출에 적용된다.
- 캐시를 바꾸면(인메모리 → SQLite) 새 캐시는 비어 있어 **첫 호출은 다시 API를 부른다**. 그래서 세 번의 첫 호출 결과 문장이 서로 다르다 (기본 temperature에서는 매번 답이 달라지는 게 정상).
- 캐시는 **같은 프롬프트 + 같은 모델 설정**일 때만 적중한다. 문장이 한 글자만 달라도 새로 호출한다.
- `set_llm_cache`는 `langchain_classic.globals`, 캐시 클래스는 `langchain_community.cache`에서 import (`langchain-community` 설치 필요, 노트북에는 주석 처리된 설치 줄이 있음).

## 5. ch07_04 — 직렬화와 역직렬화 (체인 저장/불러오기)

체인 정의를 **파일로 저장했다가 나중에 다시 복원**하는 기능. 다른 곳에서 재사용하거나 공유할 때 쓴다.

### 5.1 직렬화 가능 여부 확인

```python
ChatOpenAI.is_lc_serializable()   # True (클래스 기준)
llm.is_lc_serializable()          # True (객체 기준)
chain.is_lc_serializable()        # True (체인 전체)
```

### 5.2 체인 → 데이터

```python
from langchain_core.load import dumpd, dumps

dumpd_chain = dumpd(chain)     # 딕셔너리
dumps_chain = dumps(chain)     # JSON 문자열
```

`dumpd` 결과 구조 (요약)

```python
{'lc': 1, 'type': 'constructor',
 'id': ['langchain', 'schema', 'runnable', 'RunnableSequence'],
 'kwargs': {
   'first': {... 'id': [..., 'PromptTemplate'], 'kwargs': {'input_variables': ['fruit'], 'template': '{fruit}의 색상이 무엇입니까?', ...}},
   'last':  {... 'id': [..., 'ChatOpenAI'],     'kwargs': {'model_name': 'gpt-4o-mini', 'temperature': 0.0,
                                                          'openai_api_key': {'lc': 1, 'type': 'secret', 'id': ['OPENAI_API_KEY']}, ...}}}}
```

- 체인(`RunnableSequence`)이 **"어떤 클래스를 어떤 인자로 만들라"는 생성 명세(constructor)** 형태로 저장된다. 모델 객체 자체를 저장하는 게 아니라 **설계도**를 저장하는 것.
- **API 키는 값이 아니라 `secret` 참조(`OPENAI_API_KEY`라는 이름)로만 남는다** → 저장된 파일(`fruit_chain.json`)을 열어도 키는 없다.

### 5.3 파일로 저장 / 읽기

```python
import pickle
with open("fruit_chain.pkl", "wb") as f:      # 바이너리 쓰기
    pickle.dump(dumpd_chain, f)

import json
with open("fruit_chain.json", "w") as fp:     # 텍스트 쓰기
    json.dump(dumpd_chain, fp)

with open("fruit_chain.pkl", "rb") as f:
    loaded_chain = pickle.load(f)             # ⚠️ 이름은 chain이지만 실제로는 '딕셔너리'
```

- pickle로 저장한 대상도 체인 객체가 아니라 `dumpd()`가 만든 **딕셔너리**다. 그래서 변수명 `loaded_chain`은 헷갈리기 쉽다 (아직 체인이 아님).
- `json.dump`는 기본 설정으로 한글을 `의`처럼 이스케이프하므로 인코딩 문제 없이 저장된다 (`fruit_chain.json` 내용에서 확인 가능).

### 5.4 데이터 → 체인 (`load`)

```python
from langchain_core.load import load

chain_from_file = load(loaded_chain, allowed_objects="all")
chain_from_file.invoke({"fruit": "사과"})
```

- `load()`가 딕셔너리를 읽어 **체인 객체로 복원**한다.
- **`allowed_objects="all"`이 필요한 이유** (노트북 주석): 아무 클래스나 복원하게 두면 악의적인 파일로 임의 코드가 실행될 수 있어서 기본값은 `langchain-core` 내부 클래스만 허용한다. `ChatOpenAI`는 별도 패키지(`langchain-openai`) 소속이라 막히므로 명시적으로 허용해야 한다.
- 키는 저장돼 있지 않으므로 복원 시 **환경변수에서 자동으로 찾거나**, 직접 넘긴다:

```python
load_chain = load(loaded_chain,
                  secrets_map={"OPENAI_API_KEY": os.environ["OPENAI_API_KEY"]},
                  allowed_objects="all")
```

- JSON 파일 경로: `json.load(fp)`로 딕셔너리를 읽고 → `load(..., allowed_objects="all")`로 복원 → `invoke`.
- 세 방식(pickle, `secrets_map`, JSON) 모두 복원된 체인에서 `{"fruit": "사과"}` 호출이 정상 동작했다. 세 결과의 답변 내용이 같은 이유는 `temperature=0`이기 때문이고, 응답 `id`(`chatcmpl-...`)가 서로 다르므로 매번 새로 호출한 것이다. (이 노트북에서는 캐시를 켜지 않았다.)

### 5.5 함정

- **pickle은 신뢰할 수 있는 파일만 열 것**: `pickle.load`는 파일 내용에 따라 임의 코드를 실행할 수 있다. 여기서는 단순 딕셔너리라 pickle의 이점이 없고 **JSON이 더 안전하고 읽기 쉽다**.
- `from langchain_core.load import load, loads`에서 `loads`는 import만 하고 쓰지 않았다 (`loads`는 JSON **문자열**을 받는 함수).
- 체인 전체가 아니라 **프롬프트·모델 설정**만 저장된다. 사용자 정의 함수(`RunnableLambda` 등)가 낀 체인은 직렬화가 안 될 수 있다.

## 6. ch07_05 — 토큰 사용량과 비용 확인 (`get_openai_callback`)

> 이 기능은 **OpenAI API 한정** (노트북 마크다운 설명).

```python
from langchain_classic.callbacks import get_openai_callback

with get_openai_callback() as cb:            # with 블록 안의 호출이 모두 cb에 집계됨
    result = llm.invoke("나이지리아의 수도는 어디야?")
    print(cb)
```

출력 예

```
Tokens Used: 52
	Prompt Tokens: 16
		Prompt Tokens Cached: 0
	Completion Tokens: 36
		Reasoning Tokens: 0
Successful Requests: 1
Total Cost (USD): $2.3999999999999997e-05
```

| 속성 | 의미 |
|---|---|
| `cb.total_tokens` | 총 토큰 |
| `cb.prompt_tokens` | 입력 토큰 |
| `cb.completion_tokens` | 출력(답변) 토큰 |
| `cb.total_cost` | 총 비용(USD) |
| `cb.successful_requests` | 성공한 요청 수 |

- 두 번째 예제는 `with` 블록 안에서 `invoke`를 **2번** 호출했고 **합산** 결과가 나온다: 총 108토큰 (프롬프트 32 + 답변 76), 비용 약 $5.04e-05.
- 비용 검증: gpt-4o-mini 단가(입력 $0.15 / 출력 $0.60 per 1M 토큰) 기준 16×0.15e-6 + 36×0.6e-6 = 2.4e-5 로 일치. 단가가 바뀌면 값도 달라지므로 참고용으로만 본다.
- 콜백은 **`with` 블록을 벗어나면 집계가 멈춘다**. 마지막 `print(result)`는 블록 밖이지만 `result`(마지막 호출의 응답)는 그대로 남아 있다.
- 앞의 캐시(4장)와 함께 쓰면 **캐시에 적중한 호출은 토큰이 소모되지 않는다**.
- 오타: `"호출에 청구도니 금액(USD)"` ('청구된').

## 7. ch07_06 — Google Gemini

```python
from langchain_google_genai import ChatGoogleGenerativeAI
llm = ChatGoogleGenerativeAI(model="gemini-3.5-flash", temperature=0)
```

### 7.1 ⚠️ 핵심 함정: `content`가 문자열이 아니라 **블록 리스트**

```python
for chunk in llm.stream("안녕"):
    print(type(chunk.content), repr(chunk.content)); break
# <class 'list'> [{'type': 'text', 'text': '안녕하세요! ...', 'index': 0}]
```

- Gemini 3.x 계열은 추론(thinking)과 최종 답을 분리해 **블록 리스트**로 준다.
- `stream_response()`(teddynote 유틸)는 `chunk.content`가 문자열이라고 가정해서 **오류**가 난다 (노트북 주석 설명).
- 해결: **`StrOutputParser`를 체인에 붙이면** 블록에서 텍스트만 뽑아 문자열로 만들어 준다.

```python
chain = llm | StrOutputParser()
for chunk in chain.stream("자연어 처리에 대해서 간략히 설명해줘"):
    print(chunk, end="", flush=True)
```

- 프롬프트와 조합: `PromptTemplate("예/아니오 질문에 대답하세요. {question}는 과일입니까?") | llm | StrOutputParser()` → `"예"`.

### 7.2 `safety_setting` 오타

```python
llm2 = ChatGoogleGenerativeAI(
    model="gemini-3.1-flash-lite",
    safety_setting={ HarmCategory.HARM_CATEGORY_SEXUALLY_EXPLICIT: HarmBlockThreshold.BLOCK_NONE, ... }
)
# Unexpected argument 'safety_setting' provided ... Did you mean: 'safety_settings'?
```

- 올바른 인자명은 **`safety_settings`(복수형)**. 오타라서 `model_kwargs`로 넘어가 **원래 의도한 안전 설정이 적용되지 않았다** (경고 메시지가 알려 줌).
- 안전 설정: 유해 콘텐츠 유형(`HarmCategory`, 성적/혐오/괴롭힘/위험)별로 차단 강도(`HarmBlockThreshold`)를 정한다. `BLOCK_NONE`은 차단 안 함.
- **경고 메시지를 그냥 넘기지 말고 읽자**는 좋은 예시.

### 7.3 배치

```python
result = llm2.batch(["대한민국의 수도는?", "대한민국의 주요 관광지 5곳을 나열하세요"])
for res in result:
    print(res.content)        # 블록 리스트가 그대로 출력됨 ('extras' 안에 signature 포함)
```

- `.content`를 그대로 print하면 `[{'type': 'text', 'text': ..., 'extras': {'signature': ...}}]` 형태로 보인다. 텍스트만 원하면 `StrOutputParser`를 쓰거나 `res.text`/블록의 `'text'`를 꺼내야 한다.

### 7.4 멀티모달 (이미지 → 시)

```python
multimodal_gemini = MultiModal(llm, system_prompt="당신은 시인입니다. ...", user_prompt="다음의 이미지에 대한 시를 작성해주세요")
answer = multimodal_gemini.stream("jeju-beach.jpg")

for chunk in answer:
    for block in chunk.content:            # 블록 리스트를 순회
        if block.get("type") == "text":
            print(block["text"], end="", flush=True)
```

- ex_0914에서 익힌 `MultiModal` 클래스를 **모델만 Gemini로 바꿔** 재사용한다.
- 블록 리스트이므로 **`type == "text"`인 블록만 골라 출력**한다 (추론 블록 등은 제외).
- 이 셀은 출력이 저장돼 있지 않다.

## 8. ch07_10 — Ollama (로컬 모델)

**인터넷 API 없이 내 PC에서 모델을 실행**하는 방법. 비용이 없고 데이터가 밖으로 나가지 않는 대신 PC 사양이 필요하다.

### 8.1 Modelfile — Ollama용 커스텀 모델 정의

```
FROM EEVE-Korean-Instruct-10.8B-v1.0-Q4_0.gguf

TEMPLATE """{{- if .System }}
<s>{{ .System }}</s>
{{- end }}
<s>Human:
{{ .Prompt }}</s>
<s>Assistant:
"""

PARAMETER stop <s>
PARAMETER stop </s>
```

| 줄 | 역할 |
|---|---|
| `FROM ...gguf` | 베이스가 될 모델 파일(GGUF 형식, Q4_0 = 4비트 양자화) |
| `TEMPLATE` | 이 모델이 학습된 **대화 형식**으로 프롬프트를 감싸는 틀 (`.System`, `.Prompt`는 Go 템플릿 변수) |
| `PARAMETER stop` | 이 토큰이 나오면 생성을 멈춤 (`<s>`, `</s>`) |

- 모델마다 학습 때 쓴 프롬프트 형식이 달라서, GGUF 파일을 그냥 쓰면 답이 이상해진다. **`TEMPLATE`으로 그 형식을 맞춰 주는 것**이 핵심이다.
- 일반적인 사용 순서: `ollama create <이름> -f Modelfile`로 모델 등록 → 노트북에서 그 이름으로 호출. (노트북의 `EEVE-Korean-10.8B:latest`가 이렇게 만든 모델로 보인다. 명령 자체는 노트북에 없음.)
- 이번에 확인한 폴더 파일 목록에는 `.gguf` 모델 파일이 보이지 않았다 (용량이 커서 저장소에서 제외했거나 다른 위치에 있을 수 있음).

### 8.2 기본 사용

```python
from langchain_ollama import ChatOllama

llm = ChatOllama(model="EEVE-Korean-10.8B:latest")
prompt = ChatPromptTemplate.from_template("{topic} 에 대하여 간략히 설명해줘")
chain = prompt | llm | StrOutputParser()
stream_response(chain.stream({"topic": "deep learning"}))
```

- OpenAI 때와 **체인 구조가 완전히 같다.** `llm`만 `ChatOllama`로 교체했다.
- 영어 주제("deep learning")를 넣었는데 한국어 특화 모델(EEVE-Korean)이라 한국어로 답한다.

### 8.3 JSON 모드

```python
llm2 = ChatOllama(model="gemma:7b", format="json", temperature=0)
llm2.invoke("유럽 여행지 10곳을 알려주세요. key: 'place'.response in JSON format.")
```

- `format="json"`: 출력을 **유효한 JSON으로 강제**한다.
- 결과는 `{"key": "place", "response": [{"place": "프랑스"}, ...]}` 형태. 프롬프트의 "key: 'place'"를 모델이 `"key": "place"`라는 **필드로 잘못 해석**했다 (원래 의도는 항목 키 이름을 place로 하라는 뜻). 소형 모델이라 지시 이행이 완벽하지 않다.
- `"체코슬로바키아"`(이미 해체된 국가)가 들어가는 등 내용 정확성도 낮다 → **로컬 소형 모델 결과는 검증 필요**.
- JSON 모드로 나온 문자열은 `JsonOutputParser`(ex_0916)로 파싱해서 쓸 수 있다.

### 8.4 멀티모달: llava로 이미지 설명

```python
def convert_to_base64(pil_image):          # PIL 이미지 → JPEG → base64 문자열
    buffered = BytesIO()
    pil_image.save(buffered, format="JPEG")
    return base64.b64encode(buffered.getvalue()).decode("utf-8")

def prompt_func(data):                     # dict → HumanMessage(이미지 블록 + 텍스트 블록)
    image_part = {"type": "image_url", "image_url": f"data:image/jpeg;base64,{data['image']}"}
    text_part  = {"type": "text", "text": data["text"]}
    return [HumanMessage(content=[image_part, text_part])]

llm3 = ChatOllama(model="llava:7b", temperature=0)
chain = prompt_func | llm3 | StrOutputParser()
chain.invoke({"text": "Describe a picture in bullet points", "image": image_b64})
```

- **`prompt_func | llm3 | ...`**: 일반 파이썬 함수를 체인의 첫 단계로 바로 쓴다 (`RunnableLambda`로 자동 변환). 입력 딕셔너리를 받아 메시지 리스트로 바꾸는 **프롬프트 역할**을 함수가 한다.
- `plt_img_base64()`는 base64 문자열을 HTML `<img>`로 노트북에 표시해 이미지가 제대로 인코딩됐는지 확인하는 용도.
- 로컬 이미지는 **base64 data URL**로 보낸다는 점은 ex_0914 ch04_2와 동일하다. 다만 여기서는 `"image_url": "data:image/jpeg;base64,..."`처럼 **문자열로 바로** 넣었다 (OpenAI 예제는 `{"url": ...}` 딕셔너리). 공급자마다 허용하는 형식이 조금씩 다르다.
- 결과: 제주 해변 사진을 영어 불릿 리스트로 묘사 (열대 해변, 청록색 바다, 작은 섬, 산호초 등). **프롬프트를 영어로 썼기 때문에 영어로 답했다.**

## 9. ch07_12 — GPT4All (로컬 모델)

```python
local_path = "./EEVE-Korean-Instruct-10.8B-v1.0-Q4_0.gguf"      # 로컬 GGUF 모델 파일 경로

from langchain_community.llms import GPT4All
from langchain_core.callbacks import StreamingStdOutCallbackHandler

prompt = ChatPromptTemplate.from_template(
    """<s>A chat between a curious user and an artificial intelligence assistant.
    The assistant gives helpful, detailed, and polite answer to the user's question.<s>
    <s>Human: {question}</s>
    <s>Assistant:"""
)

llm = GPT4All(
    model=local_path,
    backend="gpu",                                   # GPU 사용
    streaming=True,
    callbacks=[StreamingStdOutCallbackHandler()],    # 생성되는 토큰을 즉시 화면(stdout)에 출력
)
chain = prompt | llm | StrOutputParser()
response = chain.invoke({"question": "대한민국의 수도는 어디인가요 ?"})
```

- Ollama와 달리 **Modelfile이 없으므로 프롬프트 템플릿에 모델의 대화 형식(`<s>Human: ... </s><s>Assistant:`)을 직접 써 넣어야** 한다. Modelfile의 `TEMPLATE`과 같은 역할을 프롬프트 문자열이 대신한다 (ch07_10 Modelfile과 비교해 보면 형식이 동일).
- `streaming=True` + `StreamingStdOutCallbackHandler`: 토큰이 생성되는 대로 출력된다. (`stream_response` 유틸 대신 **콜백**으로 실시간 출력.) 그래서 `invoke` 호출인데도 화면에는 스트리밍처럼 나온다.
- 출력 끝에 `</s></s>`가 보인다 → **종료 토큰이 결과 문자열에 섞여 나옴**. Modelfile의 `PARAMETER stop`처럼 stop 토큰을 지정하지 않았기 때문이다.
- `GPT4All`은 문자열을 넣고 문자열을 돌려주는 **LLM 클래스**(`langchain_community.llms`)라서 `Chat…` 클래스와는 입출력 타입이 다르다. 그래도 `StrOutputParser`를 붙여 같은 체인 모양으로 쓴다.

## 10. 개념 한 장 요약

### 어떤 모델을 쓸까

| 기준 | 클라우드 API (OpenAI/Anthropic/Gemini) | 로컬 (Ollama/GPT4All) |
|---|---|---|
| 성능 | 높음 | 모델·PC 사양에 따라 낮을 수 있음 |
| 비용 | 토큰당 과금 | 무료 (전기/장비 비용) |
| 개인정보 | 데이터가 외부 서버로 전송 | **PC 밖으로 안 나감** |
| 준비 | API 키 | 모델 파일, 프롬프트 형식 맞추기 |
| 결과 형식 | 공급자별로 다름 (Gemini는 블록 리스트) | 소형 모델은 지시 이행이 불안정 |

### 실용 기능

| 기능 | 코드 | 효과 |
|---|---|---|
| 캐싱 | `set_llm_cache(SQLiteCache(...))` | 같은 요청 즉시 응답, 비용 절감 |
| 직렬화 | `dumpd(chain)` → JSON, `load(d, allowed_objects="all")` | 체인 저장·재사용 (키는 저장 안 됨) |
| 토큰 추적 | `with get_openai_callback() as cb:` | 토큰·비용 집계 (OpenAI만) |
| 모델 교체 | `prompt | llm | StrOutputParser()`의 `llm`만 교체 | 공급자 변경이 쉬움 |

## 11. 공부하며 기억할 함정

1. **모델을 바꿔도 체인 구조는 그대로**지만, 응답 형식은 공급자마다 다르다. Gemini 3.x는 `content`가 **블록 리스트**라 `stream_response`가 실패한다 → `StrOutputParser`를 붙인다.
2. **인자 이름 오타는 조용히 넘어간다**: `safety_setting`(단수)은 오류가 아니라 경고만 나오고 설정이 무시된다. 실제 이름은 `safety_settings`.
3. `set_llm_cache`는 **전역 설정**이고, 캐시를 교체하면 새 캐시는 비어 있다. 캐시는 **동일한 프롬프트·설정**에서만 적중한다.
4. 직렬화 파일에는 **API 키가 저장되지 않는다** (`secret` 참조만 남음). 복원할 때 환경변수나 `secrets_map`으로 키를 공급한다.
5. `load()`는 보안상 기본적으로 `langchain-core` 클래스만 허용 → 다른 패키지 클래스는 `allowed_objects`로 명시 허용. **출처를 모르는 pickle/JSON은 열지 말 것.**
6. `get_openai_callback`은 **OpenAI 전용**이고 `with` 블록 안의 호출만 집계한다.
7. 로컬 모델은 **학습된 프롬프트 형식**(`<s>Human: ... <s>Assistant:`)을 맞춰야 답이 정상적이다. Ollama는 `Modelfile`의 `TEMPLATE`, GPT4All은 프롬프트 문자열에서 처리한다. stop 토큰을 안 주면 `</s>`가 출력에 남는다.
8. 소형 로컬 모델(gemma:7b 등)은 JSON 지시를 오해하거나 사실을 틀릴 수 있다. **결과 검증**은 여전히 필요하다.
9. 멀티모달 입력 형식은 공급자마다 미세하게 다르다 (`{"url": ...}` 딕셔너리 vs 문자열). 프롬프트 언어(영어/한국어)에 따라 답변 언어도 달라진다.
10. 실행하지 못한 셀은 출력이 비어 있다 (Anthropic은 크레딧 문제, Gemini 멀티모달 셀은 출력 미저장). 이런 셀은 **직접 실행해 확인**해야 동작을 알 수 있다.
