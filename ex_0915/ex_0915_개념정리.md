# ex_0915 개념 정리 (프롬프트)

코드 설명 없이 **이 폴더에서 등장하는 개념**만 정리한 문서다. (코드별 설명은 [ex_0915_정리.md](ex_0915_정리.md) 참고)

---

## 1. 프롬프트와 프롬프트 엔지니어링

- **프롬프트(Prompt)**: 모델에게 주는 입력 전체. 지시, 배경 정보, 예시, 질문 등이 모두 포함된다.
- **프롬프트 엔지니어링**: 모델에게서 **원하는 형태와 품질의 답**을 얻도록 프롬프트를 설계하는 일.
- 같은 모델이라도 프롬프트에 따라 결과가 크게 달라지므로, 프롬프트를 **코드처럼 관리하고 재사용**할 필요가 생긴다. → 프롬프트 템플릿.

## 2. 프롬프트 템플릿(Prompt Template)

- **프롬프트 템플릿**: `{변수}`를 포함한 **재사용 가능한 프롬프트 틀**. 변수에 값을 채워 실제 프롬프트를 만든다.
- 장점
  - 프롬프트(고정 부분)와 데이터(가변 부분)의 **분리**
  - **재사용성**과 일관성
  - 필요한 변수가 빠졌을 때 오류로 알려 줌
- **입력 변수(input variables)**: 사용자가 채워야 하는 변수. 템플릿 문자열의 `{}`에서 **자동 추출**하거나 직접 명시할 수 있다.
- **값 채우기(format)**: 템플릿 + 변수 값 = 완성된 프롬프트. 결과는 **문자열**이다.
- 체인에 연결하면 값 채우기가 **자동**으로 이루어진다. 변수가 하나뿐이면 딕셔너리 없이 값만 넘겨도 된다.

## 3. 부분 변수(Partial Variables)

- **부분 변수**: 템플릿의 변수 중 **일부를 미리 채워 두는** 기능.
- 쓰임새
  - 자주 바뀌지 않는 값을 **기본값**으로 고정
  - 여러 단계로 나눠 **변수를 점진적으로 채움**
- 미리 채운 변수는 입력 변수 목록에서 **제외**된다 (남은 변수만 나중에 입력).
- **원본을 바꾸지 않고** 일부만 채운 **새 템플릿을 파생**시킬 수 있다.
- 실행 시점에 같은 이름의 값을 주면 **미리 채운 값을 덮어쓸 수 있다.**

### 함수로 채우는 부분 변수 (동적 값)

- 부분 변수에 **값 대신 함수**를 지정하면, 프롬프트가 만들어지는 **매 순간 함수가 실행**되어 최신 값이 들어간다.
- 대표 예: **오늘 날짜, 현재 시각** 등 호출 때마다 달라져야 하는 값.
- 값을 넣으면 템플릿을 만든 시점에 **고정**되고, 함수를 넣으면 **사용 시점마다 계산**된다는 차이가 핵심이다.
- 사용자가 직접 값을 주면 함수 결과보다 **직접 준 값이 우선**한다.

## 4. 프롬프트의 외부 파일 관리 (YAML)

- **프롬프트를 코드 밖의 파일로 분리**해 관리하는 방식.
- 장점: 코드를 수정하지 않고 **프롬프트만 수정**, 여러 프로젝트에서 **재사용·공유**, 버전 관리와 협업이 쉬움.
- **YAML**: 사람이 읽기 쉬운 설정용 데이터 형식. 키-값 구조이며, **여러 줄 문자열**을 줄바꿈 그대로 저장할 수 있다.
- 파일에는 보통 **프롬프트 종류, 템플릿 문자열, 입력 변수 목록**이 들어간다.
- 한글 파일은 **문자 인코딩(UTF-8)**을 맞춰 읽어야 깨지지 않는다.
- 프롬프트 안에 **출력 양식과 분량 제한**(예: 항목 나열, 글자 수)을 넣어 답변 형태를 통제하는 것도 프롬프트 설계의 일부다.

## 5. 채팅 프롬프트 (ChatPromptTemplate)

### 5.1 메시지 기반 프롬프트

- 채팅 모델은 문자열 하나가 아니라 **역할이 붙은 메시지 목록**을 받는다.
- **역할(role)**

| 역할 | 의미 |
|---|---|
| **system** | 모델의 역할·성격·규칙을 지시 |
| **human** | 사용자의 발화 |
| **ai** | 모델의 이전 답변 (대화 맥락이나 예시로 활용) |

- **어느 메시지에든 변수**를 넣을 수 있다 (예: 시스템 메시지에 챗봇 이름).
- **문자열 프롬프트 vs 채팅 프롬프트**
  - 문자열 프롬프트: 완성 결과가 **텍스트 하나**
  - 채팅 프롬프트: 완성 결과가 **메시지 객체의 리스트** (채팅 모델에 그대로 전달 가능)

### 5.2 대화 기록 자리표시자 (MessagesPlaceholder)

- **메시지 목록 전체를 하나의 변수처럼** 끼워 넣는 자리.
- 필요한 이유: 대화 기록은 **몇 개가 들어올지 미리 알 수 없다.**
- 전형적 구조: **시스템 지시 → (가변 길이의 대화 기록) → 마지막 요청**
- 활용: 챗봇의 **대화 기록(메모리) 주입**, "지금까지의 대화를 요약해 줘" 같은 이전 대화 참조 작업.
- 모델은 **매 요청마다 이전 대화를 기억하지 못하므로**, 기록을 프롬프트에 다시 넣어 주는 방식으로 맥락을 유지한다.

## 6. 퓨샷 프롬프트 (Few-shot Prompting)

### 6.1 개념

- **제로샷(Zero-shot)**: 예시 없이 지시만으로 요청.
- **원샷/퓨샷(One/Few-shot)**: **정답 예시를 1개 또는 몇 개 함께 보여 주고** 요청.
- 효과: 모델이 **출력 형식, 말투, 추론 방식**을 예시에서 **모방**한다. 모델을 재학습(파인튜닝)하지 않고도 동작을 유도하는 **문맥 내 학습(in-context learning)** 방식이다.
- 퓨샷은 **형식·방식을 잡는 데 강하고**, 사실의 **정확성을 보장하지는 않는다.**

### 6.2 프롬프트 구조

- 최종 프롬프트 = **[지시(prefix)] + [예시들] + [실제 질문(suffix)]**
- 구성 요소
  - **예시 목록**: 입력-정답 쌍의 집합
  - **예시 서식(example prompt)**: 예시 한 개를 어떤 형태로 보여 줄지 정한 틀
  - **접두사(prefix)**: 예시 앞의 지시문
  - **접미사(suffix)**: 예시 뒤에 붙는 실제 질문 부분

### 6.3 예시 설계 개념: 단계적 추론 예시

- 복잡한 질문을 **"추가 질문 → 중간 답변 → 최종 답변"으로 쪼개어 푸는 예시**를 보여 주면, 모델도 같은 식으로 **단계별 추론**을 하도록 유도할 수 있다 (Self-ask 방식).
- 예시 텍스트의 **공백·줄바꿈·들여쓰기도 그대로 프롬프트에 포함**되므로 정돈해서 써야 한다.

### 6.4 출력의 비결정성

- 같은 프롬프트라도 모델·**temperature 설정**에 따라 답의 **형식과 내용이 달라질 수 있다.** 형식을 강하게 고정하려면 지시를 명확히 하고 temperature를 낮춘다.

## 7. 예제 선택기 (Example Selector)

- **문제**: 예시가 많으면 전부 넣는 것이 **토큰 낭비**이고, 관련 없는 예시는 오히려 방해가 된다.
- **예제 선택기**: 입력과 **가장 적합한 예시만 골라** 프롬프트에 넣는 장치.

### 7.1 임베딩과 벡터 검색

- **임베딩(Embedding)**: 텍스트를 **의미를 담은 숫자 벡터**로 변환한 것. 의미가 비슷한 문장은 벡터 공간에서 **가까이** 위치한다.
- **벡터 DB(Vector Store)**: 임베딩 벡터를 저장하고 **가까운 것을 빠르게 검색**하는 저장소 (예: Chroma).
- **의미 유사도 기반 선택(Semantic Similarity)**: 예시를 미리 임베딩해 저장 → 입력도 임베딩 → **의미가 가장 가까운 예시 k개**를 선택. 단어가 달라도 의미가 비슷하면 선택된다.
- **최대 한계 관련성(MMR)**: 유사도에 더해 **선택된 예시들끼리의 다양성**도 고려하는 방식. 비슷한 예시만 중복 선택되는 것을 피한다.
- **k**: 선택할 예시의 개수.

### 7.2 주의점

- 예시는 **벡터 DB에 저장된 상태**로 검색되므로, 예시를 수정한 뒤에는 **선택기를 다시 만들어야** 반영된다.
- 선택된 예시가 실제로 무엇인지 **직접 출력해 확인**하는 습관이 필요하다. 잘못 연결해도 **오류 없이 넘어가는 경우**가 많다.

## 8. 채팅형 퓨샷 (Few-shot Chat Message)

- 문자열 퓨샷은 예시를 **하나의 텍스트로 이어 붙인다.** 채팅형 퓨샷은 예시를 **human/ai 메시지 쌍**으로 넣는다.
- 채팅 모델의 **대화 형식과 자연스럽게 맞아떨어져** 지시·예시·실제 질문을 역할별로 구분해 줄 수 있다.
- 최종 프롬프트 구조: **system → (예시 human/ai 쌍들) → 실제 human 질문**
- 퓨샷 예시가 **출력 형식을 학습시키는 효과**가 있어, 예시와 같은 양식(예: 회의록 형식)으로 답이 생성된다.

## 9. 목적에 맞는 예제 선택 (커스텀 선택기)

- 기본 선택기는 입력의 **모든 값을 합쳐** 유사도를 계산한다.
- 입력에 **길고 제각각인 본문**이 섞이면 유사도 판단이 흐려진다.
- **커스텀 선택기**: **어떤 필드를 기준으로 유사도를 계산할지 직접 지정**한다 (예: 작업 종류를 나타내는 지시문만 비교).
- 예: "회의록을 작성해 주세요"라는 지시만 보고 **회의록 작성 예시**를 골라 주면, 본문 내용에 흔들리지 않는다.
- 선택 기준을 바꾸는 것은 **"무엇이 비슷한가"의 정의를 바꾸는 일**이다.

## 10. 환경 문제 (벡터 DB 관련)

- 벡터 DB 라이브러리는 내부적으로 **수치 계산·추론 라이브러리**에 의존해서, 설치 버전이 맞지 않으면 실행 중 **커널이 비정상 종료**될 수 있다.
- 이런 오류는 코드 로직이 아니라 **패키지 버전·환경 문제**를 먼저 의심하고 확인한다.

## 11. 개념 한눈에 비교

### 프롬프트 템플릿 종류

| 개념 | 결과물 | 언제 쓰나 |
|---|---|---|
| 일반 템플릿 | 문자열 | 단순한 텍스트 프롬프트 |
| 채팅 템플릿 | 메시지 리스트 | 역할 구분이 필요한 채팅 모델 |
| 메시지 자리표시자 | 가변 길이 메시지 | 대화 기록 주입 |
| 퓨샷 템플릿 | 예시+질문 문자열 | 예시를 텍스트로 제공 |
| 채팅형 퓨샷 템플릿 | human/ai 메시지 쌍 | 예시를 채팅 형식으로 제공 |

### 변수를 채우는 시점

| 방식 | 값이 정해지는 때 |
|---|---|
| 호출 시 입력 | 실행할 때마다 사용자가 지정 |
| 부분 변수(값) | 템플릿 생성 시 고정 (실행 시 덮어쓰기 가능) |
| 부분 변수(함수) | **프롬프트를 만드는 매 순간** 계산 |

### 예시를 다루는 방식

| 방식 | 특징 |
|---|---|
| 고정 예시 나열 | 단순하지만 예시가 많으면 비효율 |
| 유사도 기반 선택 | 입력과 **의미가 가까운 예시만** 사용 |
| MMR 선택 | 유사도 + **다양성** |
| 커스텀 선택 | **비교 기준 필드를 직접 지정** |

## 12. 핵심 요약

1. 프롬프트는 **템플릿화**해서 변수와 고정 문구를 분리하고 재사용한다.
2. **부분 변수**로 일부를 미리 채우고, **함수형 부분 변수**로 날짜 같은 동적 값을 자동 반영한다.
3. 프롬프트는 **YAML 같은 외부 파일**로 분리해 코드와 독립적으로 관리할 수 있다.
4. 채팅 모델에는 **system / human / ai 메시지**로 구성한 프롬프트를 쓰고, **대화 기록은 자리표시자**로 끼워 넣는다.
5. **퓨샷**은 예시로 출력 형식과 추론 방식을 가르치는 기법이며, 정확성까지 보장하지는 않는다.
6. 예시가 많을 땐 **임베딩 + 벡터 DB 기반 예제 선택기**로 관련 있는 것만 골라 넣는다.
7. 채팅형 퓨샷은 예시를 **human/ai 쌍**으로 넣고, **커스텀 선택기**로 유사도 판단의 기준을 원하는 필드로 좁힐 수 있다.
8. 프롬프트에 **양식과 분량을 명시**하면 답변 형태가 일정해지고, 결과는 항상 **직접 확인**한다.
